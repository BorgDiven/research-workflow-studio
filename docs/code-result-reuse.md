# 代码、运行与对比结果

新增算法建立独立代码块，并用 `parentRefs` 记录它基于哪些已有代码改进。原生代码块保留；新代码块可以调用公共原生实现，并同时支持关闭控制、开启控制等运行配置。配置变化和换图片本身不创建新代码块。已登记的代码身份保持不可变。

一个 run 记录同一代码版本按已给定的图片、配置清单提交的一批计算。该批可以包含原生模式和改进模式，无需切换版本或重新加载模型。每项产物分别记录实际配置、样本、任务和生成它的精确 run；run 状态更新不是重新执行。两个独立代码入口分别登记 run，即使它们由同一个启动脚本调用。实验通过 usage 引用产物；同一批结果可以服务多个实验。

## 对比视图独立于生产来源

代码视图继续展示该代码实际生成的结果。结果库允许跨代码、跨批次选择已有材料；不要求重跑，也不把引用改记为新代码的产出。

对比可以显式设置“方法列”：选择已有结果，填一个本次对比使用的列名，例如“原生”或“开启控制”。这些分组只描述本次对比如何展示，不证明代码等价，不改写算法或生成来源。关闭控制仍保留其他算法改动时，应标为“关闭控制对照”，不能仅凭参数为零或代码继承关系推断它是原生方法。

`comparison.viewSpec.methodGroups` 是可选数组。每组有稳定的 `id`、显示用 `label` 和完整精确的 `artifactRefs`；成员必须在该对比的 `inputRefs` 中，同一产物不能同时属于两组。`axis: "method"` 使用方法列，其余轴保留现有行为。未分组的结果仍按实际代码和配置区分，不根据标题、继承关系或参数值自动合并。

方法列仍区分实际配置、产物语义和观察时刻。跨版本的同条件结果成为候选，必须明确选择；不同配置不会被当作重复结果。每张图显示所选结果的实际代码、run 和配置，不把整列第一张图的来源套给其他样本。固定条件筛选继续逐项应用，不额外要求变更 seed 或重跑模型。

保存对比时固定候选成员和已选结果；重新打开不增加后来的新产物，也不自动选最新版本。报告可以引用这个固定对比，不是对比成立的前提。精确 run 修订缺失时显示来源缺失，不回退到同名 run 的另一修订。

## 验收范围

- 原生代码 A 和改进代码 B 保持独立；同一 B run 的不同配置保留各自产物设置。
- A、B 产生的同条件材料可显式放入同一方法列；相同样本出现多个候选时必须选择，配置差异继续分列。
- 保存、重开对比保留精确选择；跨实验引用不改变产物或生产者。
- 非成员、重复归组和缺失精确版本受到检查；旧对比无须迁移。
- 使用合成软件测试验证，不运行模型、不计算文件哈希、不修改生产研究记录。
