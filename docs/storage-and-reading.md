# 本地存储与轻量阅读

工作台把三类东西分开：项目记录、原始材料、可重建的阅读图。普通用户可以全部放在本机；外置盘不是使用前提。

| 内容 | 默认位置 | 保留规则 |
| --- | --- | --- |
| 项目数据库 | `--db` 指定的 SQLite 文件 | 保留研究关系、精确版本、结果记录和报告快照 |
| 原始材料 | 数据库同级的 `materials/` | 作为评估、复用和追溯依据，不自动删除 |
| 阅读图缓存 | 数据库同级的 `cache/previews/` | 默认最多 512 MiB，可重建的图片按使用时间淘汰 |

以下参数只改变文件的物理存放位置，不修改材料的 `/materials/...` 地址、实际生产者或已固定的报告来源：

```sh
python3 launch.py serve --db ./studio.sqlite3 \
  --materials-root /path/to/originals \
  --preview-cache-root ./cache/previews \
  --preview-cache-mb 512
```

迁移已有材料时，先复制完整目录、核对，再配置新的原件目录。不要边复制边删除旧件，也不要把原件目录当缓存清理。原件目录与缓存目录必须分离；缓存不能放进原件目录，反之亦然。更换目录不会自动搬运文件。

缓存与原件目录绑定。更换原件目录会重建阅读缓存，不修改原件；不同安装不要共用同一个缓存目录。

## “产出与对比”怎样读图

- 受管图片通过 `/api/preview?uri=<编码后的 /materials/... 地址>` 读取最长边不超过 1280 像素的阅读图，不放大较小图片。默认 WebP 质量为 85。
- 图集、对比以及点图放大使用同一阅读图。每张图旁不设“查看原图”按钮；需要原件时，从材料详情下载。
- 浏览不会顺便下载原图，也不会因为阅读图生成失败而偷偷回退到原图。不能显示时给出缺失提示，原始来源记录仍保留。
- 阅读图只是展示副本。PSNR、像素差异、其他评估及后续分析必须读取原始数据，不能拿有损阅读图代替。
- 相同受管地址复用缓存；源文件在线时核对文件大小和修改时间以刷新。没有计算文件哈希。原件离线时，尚在缓存中的阅读图仍可看；已淘汰或尚未生成的图片需要原件恢复在线。

当前转换器不自动处理动画或高位深、浮点图像。后两类需要先明确显示范围，再登记 8 位阅读图；不会自动归一化或截断像素来伪造可视效果。原始数据始终保留。

图片转换使用可选的 Pillow。基础记录服务仍可使用 Python 标准库运行；未安装转换器且没有缓存时，会显示阅读图不可用，不会安装依赖或下载原件。

```sh
python3 -m pip install Pillow
```

应在实际启动工作台的 Python 环境中安装；重启工作台后生效。原始材料接口继续支持按字节范围读取附件；`?download=1` 用于明确下载原件。

可按需查看缓存用量、清理超出上限的阅读副本，或预先生成指定材料。`prune` 只整理缓存，不删除原件；`warm` 不扫描其他目录，也不抓取远程地址。

```sh
python3 launch.py preview-cache --db ./studio.sqlite3 status
python3 launch.py preview-cache --db ./studio.sqlite3 prune
python3 launch.py preview-cache --db ./studio.sqlite3 warm \
  --uri /materials/project-a/results/result-001.png
```

如果启动服务时指定了原件目录或缓存目录，这些命令需使用相同的 `--materials-root`、`--preview-cache-root` 和容量设置。它们只管理阅读副本，不修改研究记录。

远程图片地址不会由服务器自动抓取。注册来源 URI 并不等于下载、备份或生成本地阅读图；需要先按下面的导入约定把相应材料放进受管目录。公开离线示例中的小型演示素材可以直接展示，不连接私人材料目录。

## 报告保留什么

人读的报告优先采用网页或 Markdown：研究问题、选定范围、已登记的关键指标、必要图表、已有分析和结论。完整数值、轨迹、配置与代码保留在其来源中，通过精确版本引用；不要把所有数组、所有过程图和每份原文件重新塞进报告。

`templates/report` 是一个合成信号示例：正文最多概述 12 个来源，表格只显示前 5 行和 6 列，曲线只描述点数和坐标。超出部分明确标注，完整选择仍保留在 `inputIds` 和 `evidenceSnapshot`。因此 Markdown 会变小，便携 JSON 证据快照本身仍可能较大；不能把它当作压缩归档。接入工作台后，应使用已登记材料的精确引用复用同一份原件。

已有受管 PDF 可以通过相同阅读接口生成独立的阅读版，原始 PDF 不变。可选的 `pypdf` 与 Pillow 将适合处理的 RGB/灰度图像流压缩为 JPEG 质量 90，保持原图尺寸、文本、矢量绘图、页面几何和链接；不会把整页截图后重新装进 PDF。含透明蒙版、特殊色彩空间、预测器或不支持压缩方式的图像流保持不动。

图片既可以是 PDF 资源中的独立图像，也可以直接内嵌在页面指令里。处理后一种图片时会重新编码页面内容流，但保留原有非图像绘制操作；因此内容流字节可能变化，核对应比较解析后的绘制操作、文字、页面尺寸与链接，不能要求压缩前后 PDF 字节相同。

```sh
python3 -m pip install pypdf Pillow
python3 launch.py preview-cache --db ./studio.sqlite3 warm \
  --uri /materials/project-a/reports/report.pdf
```

转换最多接受 512 MiB、1000 页、10000 个图像资源的 PDF；单幅可转换图像最多 2500 万像素，总转换工作量最多 20 亿像素。大 PDF 没有可安全压缩的图片、转换失败或新文件没有变小时，会提示阅读版不可用，不会自动改为下载原件。已经不超过 8 MiB 的紧凑 PDF（包括纯文本报告）不要求继续缩小：解析并生成独立缓存副本，输出仍限制在 8 MiB 以内。加密 PDF 不支持自动转换。PDF 阅读版与图片阅读图共用缓存容量。

检查内嵌图片时，单页内容解码上限为 64 MiB，全文件累计解码上限为 1 GiB；超出时保留原件并提示转换不可用。

报告模板本身输出 Markdown，不负责 PDF 生成。阅读版不能替代支撑结论的原始数值和图像；历史报告的固定来源不因压缩而改变。

## 模型接入与材料导入

1. 用 `rws_get_context` 定位项目与当前研究。生成新结果前，先固定代码、输入和配置；评估继续使用原始文件。
2. 把需要网页阅读的原始文件显式复制到配置的受管材料目录，使用稳定的项目内路径，例如 `project-a/results/result-001.png`。这是文件导入步骤；不要把本机任意绝对路径暴露成网页地址。
3. 通过 `rws_artifact_register` 登记 `/materials/project-a/results/result-001.png`、真实 `producerRef`、样本与实际配置。此接口只登记记录，**不会复制文件，也不会替模型执行实验**。新结果使用新路径，不覆写已被报告引用的原件。
4. 比较和报告引用已登记产物的精确版本。不要用最新版本替代旧报告的固定来源，也不要为复用已有材料虚构一次运行。
5. 第一次查看受管图片时生成阅读图；可通过 `preview-cache` 命令预先生成指定材料的阅读图。模型无需新增研究节点或改变原始来源。

## 哪些可以清理

可以自动淘汰的是已登记为缓存、且能够从原件重建的阅读图。没有归类的已有文件按原件保护。数据库、原始结果、代码与配置、评估数值、失败记录，以及论文结论依赖的中间数据应保留。

缓存上限控制阅读副本，不是整个实验目录的容量上限。原件备份和保留年限应另行安排；仅把原件搬到一块外置盘，不等于已经有两份独立备份。传输压缩包等冗余副本应在确认保留件完整后单独清理，不由阅读缓存机制删除。

macOS 后台服务的外置盘访问权限可能与终端不同。迁移时必须用正在运行的工作台验证原件下载后，再移除本机副本；若系统拦截，先保留本机原件和外置备份。不要自动为共享 Python 程序授予完整磁盘访问权限。
